# Agent workspace

This folder is the **procedural layer** of the repository. The rules live in the AGENTS pyramid: the root
[`AGENTS.md`](../AGENTS.md) first, then only the guide for the area you touch. Nothing here replaces those rules.

- `skills/<id>/SKILL.md` — a short procedure for the few tasks a guide cannot cover alone: the real window, an a11y
  audit, a performance measurement, a security audit or an incident. Each has `## Read`, `## Do` and `## Verify`. Its
  name and description are listed automatically as an available skill, but a skill is **not run automatically**: load
  it when the task matches its description, before you read code (in OpenCode, call the `skill` tool with its id). Use
  one skill per task. Rules are not skills: they live in the AGENTS pyramid and the area guides, which is where most
  tasks start and finish. `skills-lock.json` records the provenance of the two skills installed from outside this
  repository.

The read order is: root `AGENTS.md` → the routed area guide → the matching skill, if the task has one → only the deeper
docs that the guide or skill names. A skill is a procedure, not a rulebook: if it disagrees with a guide, the guide
wins and the skill is fixed in the same change.

## Guardrails

`bun run lint` runs `bun run guard`: `scripts/check-layers.ts`, `scripts/check-agent-policy.ts`,
`scripts/check-data-boundary.ts`, `scripts/check-overlay-invariants.ts` and `scripts/check-generated.ts`. They reject a
production `unwrap`/`expect`/`panic`/`todo`/`dbg`, an `#[allow]` without `reason =`, a branch on a game or loader id
outside `games/`, a provider name in a lower layer, a missing autogenerated permission, heavy work in `DllMain`, a debug
print in the hook and `unsafe` in the app crate. They are gates now; keep them green rather than adding an exception.

A destructive action (push, release, delete data, clean the worktree) needs an explicit user request; the repository
rules and the task's scope still decide.
